# Working in this repository

- Read `HANDOFF.md` at the start of a new task for current project context. Treat it as a maintained summary; verify relevant facts in code before relying on them.
- After meaningful changes or investigation, update `HANDOFF.md` before finishing: current behavior, confirmed problems and solutions, relevant validation, remaining work, and limitations. Record failed checks honestly.
- Keep the handoff concise. Replace outdated statements instead of appending a conversation transcript. Keep only useful decisions and recurring problems; put detailed history in focused documentation when needed.
- Never store credentials, authentication tokens, private prompts, or raw transcripts in the handoff.
- Preserve existing edits and do not commit unless asked.
- Keep token consumption low: focused reads, concise reports, bounded delegation when required, and checks appropriate to the change. Avoid repeating broad investigations without a reason.
- Explain practical outcomes first, followed by a concrete example when useful. Define unfamiliar terms.
